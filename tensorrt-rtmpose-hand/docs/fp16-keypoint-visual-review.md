# FP32 / FP16 大偏差关键点可视化

打开本地[人工对照页](../validation/fp16-keypoint-review/index.html)。页面不依赖服务器或网络，
可直接使用浏览器打开；每个样本也提供独立高清三联 PNG。

本轮使用公共 C++ Builder、2 GiB 的正式 TRT FP32/FP16 engine 既有 batch=1 输出，
从55个开发样本中按最大输入空间关键点偏移选择前6个。原图、固定手框、输入张量不变，
不使用诊断 engine、INT8 或最终 validation，不重新运行模型。

每个样本包含：

- 同一显示裁剪上的 FP32（蓝色）、FP16（橙色）与叠加图。
- 偏移连线；PNG 中箭头方向为 FP32→FP16。
- 默认标出偏移最大的3个点，可打开全部编号，编号从0开始。
- 可分别关闭叠加图上的 FP32、FP16 和连线。
- 可展开原图位置、21点分数/valid/偏移表，并下载 CSV。

| 样本 | 最大偏移点 | 输入坐标偏移 / px | 原图坐标偏移 / px |
| --- | ---: | ---: | ---: |
| F0012-D000 | 3 | 23.585 | 12.912 |
| F0010-D001 | 4 | 19.500 | 4.883 |
| F0031-D000 | 0 | 18.007 | 6.069 |
| F0008-D000 | 3 | 2.236 | 0.643 |
| F0043-D001 | 1 | 2.062 | 0.569 |
| F0022-D000 | 16 | 1.803 | 1.631 |

输入偏移以256×256模型坐标计，原图偏移来自冻结逆变换后的坐标。
显示裁剪边长为1.6×bbox最大边，再放大至640×640，仅用于观察，不是新的模型输入。
因此屏幕上测得的距离不等于报告中的输入/原图像素距离。超出原图的显示区域填零，
黑色边缘不能当作实际图像内容；应结合展开的原图确认可见性。

FP32仅为数值参考，并非人工真值。所有有效点均绘制，不额外按score筛选。

[生成脚本](../scripts/visualize_fp16_outliers.py) 在绘图前核验两份正式engine身份、cases、
推理完成清单中的全部文件哈希和原图哈希，并检查Python坐标还原与已有C++结果一致。
输出 `manifest.json` 记录所选样本、显示变换和生成文件哈希。
本轮已检查全部HTML资源、6样本/126关键点数量、文件哈希与最差样本数值，并查看了生成的样例图。

重复生成须使用新的输出目录，避免覆盖评审产物：

```bash
/home/ssd/anaconda3/envs/py38/bin/python \
  tensorrt-rtmpose-hand/scripts/visualize_fp16_outliers.py \
  --count 6 --output /tmp/rtmpose-fp16-keypoint-review
```

[修正前后四精度对照页](../validation/corrected-bbox-review/index.html)。

修正版cases、NPY、裁剪、四份C++推理输出和来源manifest独立保存，
不覆盖原development张量、校准数据及历史55样本报告。
生成入口为 `scripts/review_corrected_bbox.py`，输出目录存在时拒绝覆盖。

四个既有engine均完成image路径推理，Python与C++原图解码差小于1e-9，
四版预处理输入逐元素一致。此处只有一个样本，不能据工具输出宣称重新验证了实际batch2/3/4。

没有将此结论扩展到未展示样本、未启用FP16 fallback的INT8或最终validation。
